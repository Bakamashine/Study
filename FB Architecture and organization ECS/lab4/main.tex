  \section{Система управления обучением (Moodle)}
Данные системы были созданы для дистанционного обучения. Такие платформы созданы для того, чтобы учителя могли свободно настраивать задания, оценивать и даже выставлять оценки. Самой известной на сегодняшний день является платформа Moodle. \par
{\bfseries{Moodle}} - это абсолютно бесплатная система управления курсами с открытым исходным кодом, специализирующаяся для эффективного онлайн-обучения.
Благодаря потребности в образовании и открытому исходному коду (\href{https://github.com/moodle/moodle}{Github}), существует множество сайтов которые открыты по всему миру, в одной только России открыто 4343 сайта (\href{https://stats.moodle.org}{Moodle statistics}). Основным языком, на котором он написан, является PHP. 
\href{https://moodle.org}{Official Moodle site}
\subsection{Назначение системы}
Данные CMS нужны в первую очередь для учебным заведений, которые имеют множество студентов, а так же для дистанционного обучения. Бывает проблема, что если студентов очень много или обучение предполагает дистанционный вариант, то такие платформы как Moodle - целое спасение. Преподаватель может выставить задание или тест со своими сроками сдачи. Так же, преподователь может проверять задания на платформе и выставить за неё оценку (Некоторые такие сайты могут иметь свой "электронный" дневник). На сайте можно публиковать объявления, учебную информацию и записи лекций.
\subsection{Описание}
\subsubsection{Назначение системы, решаемые задачи, целевая аудитория.}
Многие такие сайты (Moodle) имеют монолитную архитектуру. Существует множество плагинов, которые позволяют расширить возможности, соотвественно, существуют и плагины которые могут добавлять api.
\subsubsection{Архитектура}
В основном CMS писались (и пишутся) на языке PHP. Это скриптовый язык с динамическими типами, который появлился ещё в 1994 году (\href{https://www.php.net/manual/en/history.php.php}{PHP History}) и по сей день является актуальным языком для веб-разработки. Из-за развитых инструметов PHP для управления базами данных (PDO), Moodle может работать со множеством баз данных: PostgreSQL, MariaDB, MySQL, Oracle Database, Microsoft SQL Server.
\subsubsection{Функциональные подсистемы и их взаимосвязь.}
Moodle может использовать такие подсистемы как Web Services API (REST, SOAP, XML-RPC). Существуют ещё такие службы для интеграции контента на сайт: LTI (Главный стандарт для подключения внешних образовательных инструметов (антиплагиат)), SCORM (протокол для передачи прогресса и результатов прохождения тестов), xAPI (Стандарты для сбора подробной аналитики об учебном опыте).

\subsection{Механизмы обеспечения надёжности}
Moodle имеет несколько методов управление доступом.
\begin{itemize}
    \item Ролевая модель - позволяет гибко настроить права для пользователя (студент, преподователь, гость).
    \item Методы аутентификации - сайт на Moodle может включать в себя несколько способов входа (Через почту Google, VK и др.), а так же поддерживает другие протоколы аутентификации (OAUTH). 
    \item Защита от XSS и SQL - инъекций
    \item Безопасность загрузки и просмотра файлов - При открытии файла, идёт обращение к скрипту autoload.php в который передаётся GET параметром путь до файла и уже этот скрипт решает как отдать нам файл. Если это файл кода - то он его просто даст на скачивание, если же это .pdf документ или же .docx (если сайт поддерживает открытие документов такого формата), то откроется в браузере. 
\end{itemize}

\subsection{Оценка масштабируемости и производительности}
При высокой нагрузке, сайт Moodle может проседать в производительности из-за своей монолитности. Есть плагины которые могут предоставить RESTAPI и с помощью него разделить отвественность (Moodle сайт использовать как backend и написать свой фронтенд), но в этом есть минус в том что разработка такого решения займёт много времени (Moodle очень много что предоставляет из коробки, в случае же с фронтендом, писать и реализовывать придётся крайне много). \par
Сайт отлично внедряется в учебный процесс. В техникуме, в школе или в вузе - неважно. Почти все сайты учебных заведений сделаны на Moodle. Помимо учебных сайтов, существуют так же сайты и с научными работами.

\subsubsection{Особенности интеграции с другими системами.}
Moodle предоставляет несколько уровней интеграции. Прежде всего, это встроенные веб-сервисы (Web Services): REST (основной и рекомендуемый вариант), а также устаревшие SOAP и XML-RPC. Администратор включает веб-сервисы и выпускает токен доступа; внешнее приложение обращается к endpoint webservice/rest/server.php, передавая wstoken, имя функции и параметры, а ответ получает в формате JSON или XML. Через эти функции можно программно создавать пользователей и курсы, управлять зачислением, получать оценки и списки курсов. Тот же API использует официальное мобильное приложение Moodle.

Для связи с другими образовательными сервисами применяются открытые стандарты. Протокол LTI (особенно LTI 1.3 с расширением LTI Advantage) позволяет подключать внешние инструменты — системы проверки на плагиат, видеоконференции, интерактивные задания — с передачей оценок и списков участников прямо в журнал Moodle. Формат SCORM 1.2/2004 даёт возможность импортировать готовые учебные модули ZIP-архивами и отслеживать прогресс, затраченное время и результаты прохождения. Стандарт xAPI (Tin Can) в связке с внешним хранилищем LRS (Learning Record Store) собирает подробную аналитику учебных действий, в том числе вне самой платформы. Для обмена данными также используются IMS QTI и Moodle XML (банк вопросов), CSV (пользователи и оценки), подписки календаря iCal и ленты RSS.

Аутентификация может быть вынесена во внешнюю систему: поддерживаются LDAP, SAML 2.0, Shibboleth, CAS, OAuth 2/OpenID Connect и подключение к внешней базе данных, что позволяет организовать единый вход (SSO) и централизованное управление учётными записями. Система плагинов и событийная модель (Event API) дают возможность реагировать на события, запускать фоновые задачи и передавать данные в электронный дневник, систему аналитики или корпоративные сервисы. К ограничениям относятся монолитность ядра, зависимость плагинов от версии Moodle, необходимость использовать HTTPS и надёжно хранить токены, а также сложности при массовой синхронизации через API — в таких случаях интеграционную логику обычно выносят в отдельный сервис-посредник и кэшируют часто запрашиваемые данные.
